Nix can hand Emacs extra ~org-agenda-files~, and can generate some of them
from published Outlook calendars.  The Emacs side lives in ~emacs-config~ as
~lisp/nix-org-agenda-config.el~ and knows nothing about where the files come
from.

* The contract

~programs.emacs.org-agenda.files~, declared in
~agnostic-modules/emacs-org-agenda.nix~, is a list of absolute paths.  When it
is non-empty, home-manager writes ~~/.config/emacs/nix-org-agenda.json~ for
~programs.emacs.org-agenda.user~:

#+begin_src json
{ "org-agenda-files": [ "/Users/me/notes/agenda/generated/work.org" ] }
#+end_src

Emacs reads the file at startup and appends each existing path to
~org-agenda-files~.  A missing file, a missing key, or an unparsable file
yields a warning in ~*Warnings*~ and an empty list.  A listed path that does
not exist yet yields a warning and is skipped, since org would otherwise
prompt at startup.  Listed files are also added to ~revert-without-query~, so
a regenerated file reloads without a prompt.

Extra files can be declared directly:

#+begin_src nix :exports code
programs.emacs.org-agenda.files = [ "/Users/me/notes/shared/team.org" ];
#+end_src

* Outlook calendars

~programs.emacs.org-agenda.outlook-calendars~, declared in
~darwin-modules/emacs-org-agenda-outlook-calendars.nix~, fetches each
published ICS feed on an interval, expands recurring events with
~ical2orgpy~, and atomically replaces ~<outputDirectory>/<name>.org~.  The
path is appended to ~files~ automatically.

#+begin_src nix :exports code
programs.emacs.org-agenda = {
  user = "me";
  outlook-calendars = {
    enable = true;
    outputDirectory = "/Users/me/notes/agenda/generated";
    calendars.work.rekeyFile =
      ../secrets/issued/outlook-work-${host-id}-ics-url.age;
  };
};
#+end_src

A published Outlook link carries its access token in the URL, so the URL is
an agenix secret.  Outlook on the web issues the link under Settings,
Calendar, Shared calendars, Publish a calendar.  Take the ICS link, not the
HTML one.

** Adding a calendar in a private wrapper

You can generate a new URL via the [[https://outlook.office.com/calendar/options/calendar/SharedCalendars][Shared Calendars]] section of the web version
of Outlook.  The =Publish a calendar= subsection is where you can select a
calendar and "publish" a link.  This generates the link.

The URL is private, so the secret belongs to the wrapper flake, following
[[file:private-wrapper.org::*Wrapper-owned secrets][Wrapper-owned secrets]].  From the wrapper's root:

#+begin_src sh :exports code
agenix edit secrets/issued/outlook-work-scandium-ics-url.age
git add --intent-to-add secrets/issued/outlook-work-scandium-ics-url.age
agenix rekey --add-to-git
#+end_src

~agenix edit~ does not add the file to git, and ~agenix rekey~ evaluates the
flake, which only sees git-visible files.  The wrapper also needs
~age.rekey.localStorageDirs = [ ../secrets/rekeyed/${host-id} ];~ so the
rekeyed copy has somewhere to live.

** Operating it

- Force a run with
  ~launchctl kickstart gui/$(id -u)/org.nix-community.home.outlook-<name>-sync~.
  This is required when the service changes due to an issue with ~nix-darwin~
  with user ~LaunchAgents~.
