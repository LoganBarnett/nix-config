#+title:     Global Claude Instructions
#+language:  en

* Documentation

** Character Set

Write only ASCII.  Humans must be able to type and search the text.

** Document format

This document is written in org-mode.  A tilde-slash literal such as ~/foo~ is
the verbatim text =/foo=.  It is not a home-directory path.

Prefer org-mode for new documents.  Use markdown only when something requires it
or the project already uses it.  GitHub never requires markdown.

** Prose conventions

*** Be Concise

Be concise on all prose.  This includes both prose emitted to disk and to the
operator.

*** Two Spaced Sentence Breaks

Put two spaces after sentence-ending punctuation.  Skip this only where a
formatter strips it.  Known formatters that do:

1. ~elm-format~.
2. Whatever markdown formatter we've been using in some places.

* Nix

** Explicit ~default.nix~ paths

Write ~default.nix~ explicitly.  Use ~pkgs.callPackage foo/default.nix~, not
~pkgs.callPackage ./foo~.  A project that already imports directories implicitly
keeps its pattern.

* Dev environment

Build non-trivial projects in Rust unless told otherwise.  Scaffold them with
the ~/new-rust-project~ slash command.  It wraps
=~/dev/rust-template/new-project.sh=.

** Global tools

Never use tools that download or install software globally.  ~bundler~,
~rustup~, and ~brew~ are examples.  This is a Nix environment.

Project tools such as ~cargo~, ~go~, and language runtimes belong in the
project's ~flake.nix~ under ~devShells~.  ~direnv~ activates the dev shell.  Run
the tool directly.

** Command-line JSON parsing

Use ~jq~ for command-line JSON.  It is on every host.  Do not use ~python3~.  It
is not reliably on ~PATH~.

* Git workflow

** Leave changes unstaged

Staging is the user's review signal.  Never stage or unstage files unless asked.
Leave every change in the working tree.

Commit only when asked.  A commit holds exactly what the user staged.  Push only
when asked.

New files in a Nix flake repo are the exception.  Use ~git add --intent-to-add~
on each.

** Use ~git worktree~ for ongoing branch work

For any branch work beyond a simple, authorized branch + edit + commit + push
workflow, use ~git worktree~.  The placement pattern is
~../<repo>.worktrees/<branch>~.

Clean up the worktree when work is merged and the worktree is clean.

* Program Arguments in Code

Use a program's long arguments whenever it has them.  A short argument with no
long form gets a comment at each use.
